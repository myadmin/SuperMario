### 3.1 瓦片交互：顶碎砖块

1-1 的砖块在 `cols 168..171 / row 9`（世界坐标 x 2688..2751, y 144..159）。
把 Mario 放到正下方（x=2700，相机随之变为 2600），再给一个向上速度去顶砖，
逐格读取画布像素（天空色 `156,155,255` 即表示该格已被移除）：

| 格子 | 顶砖前 | 顶砖后 |
|---|---|---|
| col168 | 砖块 256px | **天空 256px**（已顶碎） |
| col169 | 砖块 256px | 砖块 256px |
| col170（`?` 块） | 254px + 2px 天空 | 不变 |
| col171 | 砖块 256px | 砖块 256px |

只碎一格是**正确行为**：`Solid.obstruct` 在第一格命中后立即把 `vel.y` 置 0，
同一帧内后续匹配不再进入 `brick.handleY` 的 `vel.y < 0` 分支。这与上游
`TileCollider.handle` 的逐字移植一致。

结论：`TileCollider` 的行为派发、`brick` 处理器、网格删除与碎块生成均工作正常。

## 4. 与原版的差异（均为有意改动）

| # | 原版行为 | 复刻版 | 原因 |
|---|---|---|---|
| 1 | `splice(layers.length - 1, 0, spriteLayer)` 把角色层插在最后一层背景**之前**，装饰层（云/灌木/山丘/管道）盖住角色，1-1 开局看不到 Mario | 改为 `push`，角色层位于所有背景层之上 | **修复**：这是原版的渲染缺陷，会让人误以为游戏坏了 |
| 2 | 无条件 `push(createCollisionLayer(level))`，画面常驻红/蓝调试框 | 默认关闭，`?debug=1` 可还原 | **修复**：调试脚手架不应作为交付外观 |
| 3 | CSS `.aspect-4-3` 把 256×240 拉伸成 4:3（横向 ×1.25） | 原样保留 | 这是原版的视觉特征，保留以维持外观一致 |

除以上三项外，**页面布局、加载页、过渡页与原版逐像素一致**；关卡数据、精灵规格、
音频与渲染管线均为原版原样。

> 另一项有意的新增（不算上表那种「原版行为」差异）：**加命时头顶的「1UP」飘字**
> （`engine/scorePopups.ts`，见 §6.14）。原版关卡内的 HUD 里本来就没有命数，本项目也不打算
> 为此改 HUD 布局（那是原版逐像素的一部分），所以改成在吃到命的那一刻直接飘一下。

### 6.1.1 一次性语义（修复「无限跳顶」）

上表是 CDP 实测的画布/像素观测。顶过之后的行为另用一份临时的无头检查复核
（esbuild 打包后直接在 node 里驱动真实的 `TileCollider` + `chanceBlock` 行为，
不经浏览器与渲染层，18 项断言全过，验证后已删除）：

| 断言 | 结果 |
|---|---|
| 第一次顶（`col 16 / row 9`，`vel.y = -175`、头顶越过方块底边） | 金币 1、分数 200、方块上弹、弹出 1 枚金币实体、马里奥被挡在方块底边（`bounds.top = 160`、`vel.y = 0`） |
| 第二次顶同一格 | 金币仍为 **1**、分数仍为 **200**、不再弹出金币；方块已换成 `metal`（外观）与 `ground`（行为） |
| 同一段 range 展开出的相邻两格（`[20,2,9]`） | 顶左格后左格变实心、**右格仍是问号块**且仍能单独发货（1 枚），原始 tile 对象未被就地改写 |

### 6.1.2 蘑菇道具（修复「蘑菇没有出现」）

**症状**：顶开本关第一枚问号块后，既看不到蘑菇，也没拿到道具。

**根因**：`entities/Mushroom.ts` 把「只画方块顶边以上的部分」这条裁剪无条件套在所有帧上。
钻出期间它是对的（蘑菇确实在方块里往外冒），但蘑菇钻完之后会向右走、走出方块边缘并掉下去，
那一刻它的 `pos.y` 已经大于方块顶边，裁剪高度算出来变成 0 —— 整只蘑菇被裁没了。孤立的问号块
（`col 16 / row 9`，两侧没有平台）尤其明显：蘑菇冒出后 0.35s 就走出方块右缘，随即消失。

**修复**：裁剪只在 `Emerging.done === false`（还在钻）时生效，钻出之后整只都画。
另外给 `MushroomPickup.collides` 加了一条：**钻出期间不可拾取**。否则马里奥贴着方块底边顶它时，
两者包围盒（方块底边 y=160 vs 蘑菇起始底边 y=160）会在蘑菇冒出来之前就重叠，蘑菇被瞬间吃掉——
玩家只看到分数 +1000、马里奥变大，却看不到蘑菇。

**CDP 实测**（1-1，真按键跳跃：站在地面 (256,192) → 起跳顶到 `col 16 / row 9` 的方块，
相机 156，方块在屏幕 x=100）：

| 帧 | 蘑菇世界坐标 | 画布红色像素（红伞 `d82800`，扫描 y 100–224 全宽） | 分数 / 马里奥 |
|---|---|---|---|
| 顶开 +11 帧 | (256,143.5) 冒出中 | 16 px，包围盒 (103,141)–(112,142) | 0 / 小 |
| +40 帧 | (256,128) 冒完 | **52 px**，包围盒 (101,129)–(114,136) | 0 / 小 |
| +64 帧 | (273,129) 走出方块、开始下坠 | 52 px，包围盒 (118,130)–(131,137) | 0 / 小 |
| +80 帧 | (285,192) 落到地面 | 52 px，包围盒 (130,193)–(143,200) | 0 / 小 |
| +120 帧 | (315,192) 继续向右走 | 52 px，包围盒 (160,193)–(173,200) | 0 / 小 |

即：**从钻出到在地面行走，每一帧都在画布上（130 帧里 117 帧扫到红伞像素）**，
蘑菇不会在走出方块时被裁没；同时站在方块下的马里奥没有被它碰到（分数仍为 0、仍是小马里奥）。
之后马里奥碰到它时分数 +1000、碰撞盒变成 14×32、蘑菇从关卡实体里消失。

另有 21 项无头断言复核整条链路（esbuild 打包后在 node 里驱动真实的 `TileCollider` / `Level` /
实体循环，不经浏览器与渲染层，验证后已删除）：第一枚出蘑菇且不直接加分、方块变 `metal`、
0.5s 后停在方块顶上一个身位、随即以 45px/s 向右走、走出方块后落到地面、钻出期间吃不到、
碰到后 14×32 + 1000 分 + 蘑菇移除、第二枚仍出金币 +200、回头再顶已使用方块无反应、
大马里奥再吃只加分不变尺寸、换关后重置。

### 6.1.3 隐藏块与 1-UP 蘑菇（修复「这枚方块本来不该出现」）

**症状**：1-1 第 64 列第 8 行、大山丘正上方悬空着一块实心方块，默认就画在画面上；
用户指出它本该看不见，并且跳起来顶它应该出一枚加命蘑菇。

**判据**：该格在关卡数据里是 `{"style":"metal","behavior":"ground","ranges":[[64,8]]}`，
而整个 1-1 只有这一处 `metal`。它的位置与 NES 版 1-1 的隐藏 1-UP 块一致
（`_backup/js/level.js` 里的注释正是 `Hidden 1-UP Block (at col 64, row 8)`）。另外把用户在
页面上圈出的那枚方块逐像素还原，颜色恰为 `metal` 瓦片的 `#a35d00` + 黑描边 `#000000`
（不是问号块的 `#e79c21`），排除了「其实是个问号块」的可能。

**修复**：关卡数据里的每个 `metal` 瓦片都当作隐藏块（默认不绘制、仍然实心、从下方顶开才现身
并换成已使用方块）；内容由 `HIDDEN_BLOCK_CONTENTS` 决定，1-1 那枚出 1-UP 蘑菇，其余出金币。

**CDP 实测**：把 rAF 停掉、用 `handle.update(1/60)` 逐帧手动驱动（这样测试可复现，不受
过渡页/后台标签页影响）。马里奥压在 (1024,·)，相机 `pos.x` 稳定为 **924**，方块落在屏幕 x=100。

| 观测 | 结果 |
|---|---|
| 顶之前，屏幕 (100,128,16×16) | 整整 256 个像素全是天空色 `#9c9bff` —— **默认不可见**（修复前这里是完整的 `metal` 方块） |
| 从下方顶它（`pos=(1024,144)`、`vel.y=-200`）之后同区域 | 16×16 的 `metal` 图案：黑描边 + `#a35d00` 块体 + 四角铆钉，整体上移 **10px**（上弹动画）—— **现身** |
| 顶的同时 | 金币仍 0、分数仍 0（1-UP 块不出金币） |
| 顶完的马里奥 | `bounds.top` 停在方块底边、`vel.y` 由 -200 变 25（被弹开后下落）—— 隐藏期间也**是实心的** |
| +35 帧，画布 (104,113)–(117,120) | 绿色 `#1b9d00` 52px，逐像素 dump 得到绿伞 `G` + 白斑 `W` + 奶油菌柄 `S` + 黑眼睛 `K`（与红蘑菇同一张 16×16 像素图，只换伞盖颜色） |

| 走过去碰到它 | 命数 **2 → 3**（当时是 2，因为测试过程中马里奥掉坑死过一次）、金币仍 0、分数仍 0（**加命不加分**）、画布上绿色像素归零（蘑菇消失） |

| 回归：普通问号块 `col 16 / row 9` | 顶开仍然出（本关第一枚的）红蘑菇 `#d82800`，方块同样变成 `metal`；站在顶开的方块上不掉下去（⚠️ 这一格当时命中的是旧规则「本关第一枚出蘑菇」，出物规则已在 §6.7 改成按马里奥大小出货，`16,9` 现在是道具块：小马里奥出蘑菇、大马里奥出火花） |

### 6.4 背景音乐开关

原版没有开关（`MusicPlayer.playTrack()` 无条件 `play()`）。新增的开关在页面右下角，
状态存在 `localStorage.super-mario:music`（`'off'` 之外的任何值都算开，默认开）。

在运行中的页面上直接读 `level.music.player.tracks` 里各 `HTMLAudioElement` 的
`paused` / `currentTime`（`main` 是关卡主题，`hurry` 是时间快到时插播的加速主题）：

| 操作 | `main.paused` | `main.currentTime` | `localStorage` | 按钮文字 |
|---|---|---|---|---|
| 开局（默认开） | false | 11.90 → 12.50（在走） | — | `♪ 音乐 开` |
| 点右下角开关 | **true** | 12.50（**冻结**，0.6s 内推进 0） | `off` | `♪ 音乐 关` |
| 再点一次 | **false** | 12.50 → **13.10**（从原处接着放，不是从头） | `on` | `♪ 音乐 开` |
| 按 `M` | 同上（两次按即两次切换） | — | `on` / `off` | 同步更新 |
| `Ctrl+M` / 长按重复键 | 不触发 | — | 不变 | 不变 |
| 关掉后**刷新页面** | 开局时保持 **true**（`current` 已是 `main`，但没有 `play()`） | 0 | `off` | 刷新后直接是 `♪ 音乐 关` |

同时验证了两点实现细节：点开关后 `document.activeElement` 不是按钮（否则之后按空格/
回车会重复触发它）；换关时 `SceneRunner` 会对旧关卡调 `pause()` → `pauseAll()` 把
「当前曲目」清空，所以换掉的旧播放器不会被开关重新唤起（开关只驱动最后一次
`playTrack()` 登记的那个播放器）。

### 6.7 道具按马里奥大小出货 + 火花 / 火球（修复「大马里奥顶出来的还是蘑菇」）

**症状**：无论马里奥是大是小，第一枚被顶开的问号块都给蘑菇。**根因**是上一轮出物规则本身：
当时用的是「本关第一枚被顶开的问号块出蘑菇」（`features/chanceBlock.ts` 里的模块变量
`mushroomGiven`），它既不区分方块、也不看马里奥大小，与原版规则不符。现在改成两个条件：
`POWERUP_BLOCKS`（关卡名 + 格子坐标，决定哪些方块装道具）+ `PowerState.large`（顶的那一刻
马里奥大不大）——**小 → 变大蘑菇，大 / 火力 → 火花**。

**CDP 实测**（先 `handle.start()` 重载一份全新的 1-1，再驱动真实引擎逐帧读运行时状态与画布像素）：

### 6.8 上弹方块下面那半块「旧方块」（修复「顶起时底部多一个置灰石块」）

**症状**：顶问号块的那一瞬间（方块整体上移 10px / 0.2s），它的原位置下方还留着半块方块 ——
不是弹出的金币、也不是已使用块，而是**上一帧**的方块像素，看上去就像底下多压着半块灰石头。
原版没有这个（原版方块上弹时，原位就直接露出天空）。

**根因**是两层叠起来的：

1. `layers/background.ts` 的上弹位移原来只按 `${indexX},${indexY}` 记录，而关卡有**多层背景**
   （1-1：第 0 层是「天空 + 地面」、第 1 层才是真正的瓦片），两层都会读到同一个偏移 —— 天空层
   里那一格也跟着上移 10px。天空是不透明的，一移开就在原位留下 10px 的**透明洞**。
2. `Compositor.draw()`（与上游逐字一致）**不清画布**：图层没画到的地方会保留上一帧的像素。
   洞的位置正好露出上弹之前那一帧的方块下半部分（问号块的暗色帧看起来就像一块灰石头），
   于是画面上就是「被顶起的新块 + 上一帧的旧块」两个方块叠着。

**修复**：`tileOffsets` 的每一项改成 `{ offset, tile }`，绘制时只有 `bump.tile === tile`（同一格、
**同一个瓦片对象**）才应用偏移；`features/chanceBlock.ts` 的 `consumeBlock()` 把「顶完写进网格的
那个新对象」传给 `bumpTile()`。天空层里那一格是另一张瓦片对象，因此不动，原位正常露出天空。

**CDP 实测**（1-1，逐帧 dump 被顶那一列 16×32 的像素、颜色转字符）：

| 时刻 | 修复前 | 修复后 |
|---|---|---|
| 顶起第 1 帧（偏移 -10） | 134-149 = 已使用块，**150-159 = 上一帧的方块（残留）** | 134-149 = 已使用块，**150-159 = 天空**（金币块则是弹出来的金币，那是本就应该有的） |
| 第 8 帧（偏移约 -5） | 140-155 = 块 + 残留 | 140-155 = 块，其余是天空 |
| 第 14 帧（回落完） | 144-159 = 已使用块 ✓ | 144-159 = 已使用块 ✓（两边一致） |

三条路径都复测过：道具块（`[16,9]`，出蘑菇）、金币块（`[23,9]` / `[170,9]`，弹金币）、
隐藏块（1-1 `[64,8]`，现身 + 上弹 + 绿蘑菇从块里钻出来）——上弹照旧，原位不再有残留。
另外把 25 个关卡里 **26 处隐藏块坐标**全部核对了一遍：每一格在更早的图层里都有瓦片盖着，
所以「隐藏时跳过绘制」这一条不会留下同样的透明洞。

`npm run typecheck` / `npm run build` 均通过，`public/` 未改。

### 6.9 1-2 的三处修复（问号块内容 / 两道坑的升降桥 / 结尾横管）

**症状**（用户报告）：1-2 开场那排五枚问号块里，小马里奥顶上去**拿不到应得的东西**；

`'uw-exit' → '1-3'`。

### 6.13 火球打死敌人后仍然会撞死马里奥（修复「放子弹打死小怪，马里奥碰上还是会死」）

**症状**：吃了火花发射火球，明明打中了板栗仔，马里奥走上去还是掉血。

**根因（两层，缺一不可）**：

1. `Killable.kill()` 只是把 `dead = true` 排进任务队列，而任务队列在 `Entity.finalize()` 里执行
   —— 也就是**这一帧的实体碰撞检测全部跑完之后**。因此被打死的那一帧，敌人在碰撞检测里仍然
   是「活的」。
2. 火球过去是在 `collides`（碰撞阶段）里打死敌人的，而 `Level.update()` 一帧的顺序是
   「所有实体 update」→「所有实体两两碰撞」→「finalize」。同一个碰撞阶段里「敌人撞到马里奥」
   与「火球打到敌人」谁先谁后**只取决于实体在集合里的插入顺序**，而马里奥永远排在新生成的
   火球前面 —— 于是近距离对射时就会出现「火球在这一帧打死了它、它在同一帧里也打死了马里奥」。

**修法**：

- `Killable` 增加**立即生效**的 `killed`（以及死因 `cause`）；所有杀伤判定（`Goomba` / `Koopa` /
  `Bullet` / `CheepCheep` 的 Behavior）改读 `killed || dead`，`dead` 保留上游语义（渲染 / 计时 / 移除）。
  踩扁仍然照旧：`dead` 未置位时 `Stomper` 照常弹起（`Killable.kill()` 第一次判死的原因也保留）。
- 火球的命中判定从 `collides` 挪到它自己的 `update` 里（`Physics` 之后、**任何碰撞检测之前**）：
  命中一旦发生，被命中者在本帧剩下的时间里已经是 `killed`，任何碰撞检测都到不了它。
- 新增 `traits/Flipped.ts`：被火球打翻的敌人按原版**翻过来、直直掉出画面**（160px/s、
  穿地形、掉到 240 以下就删），不再画「踩扁」帧、也不在原地走 2 秒。翻转帧素材里没有，所以和
  火球 / 蘑菇一样在绘制时现做（包一层 `entity.draw`，绕 `offset.y + size.y` 垂直镜像）。
- 顺带补上 `entities/CheepCheep.ts` 的两处：鱼**连 `Killable` 都没有**（火球只能从它身上穿
  过去），而它的杀伤判定是无条件的 `them.kill()` —— 一旦补上 `Killable`，一条已经打翻的鱼会
  永远撞死马里奥，所以两处一起改（先看自己的 `killed || dead`）。

**实测**（全部在运行中的 1-1，逐帧手动推进 + 读画布像素）：

| 场景 | 观测 |
|---|---|
| 距离扫描（gap 0→16px，每档重开一局） | gap ≥ 4：`deadFrame` 0~1、**`hurtFrame` 全程 −1**、`marioLevel` 保持 `fire`；gap 0/2 仍会挨一下（那时板栗仔已经贴在马里奥身上，且马里奥被击中时 `Fire` 会拒绍发射——这是对的） |
| 打翻后的外观 | 画布上抓 16×16：打翻的那一格 = 正常帧**逐行上下镜像**，`diffPixels = 0`（256 像素全等），非天空像素 **221** 个（确实画出来了，不是空白） |
| 打翻后的下落 / 移除 | 12 帧下落 32.4px（= 160px/s），约第 18 帧（0.3s）从关卡里移除；`Solid.obstructs = false`、`PendulumMove.enabled = false` |
| 打翻的尸体贴到马里奥身上（5 帧） | 不受伤、`marioLevel` 保持 `fire` |
| 回归：踩扁板栗仔 | 第 6 帧判死、`cause = 'default'`、`flipped = false`（仍画「踩扁」帧）、弹起 `vy = −400`、马里奥不受伤 |
| 回归：站在踩扁的尸体上（6 帧） | 不重复受伤 |
| 回归：活着的板栗仔撞小马里奥 | 第 1 帧 `dying = true`（照旧会死） |
| 回归：乌龟 | 侧面撞 → 小马里奥死亡；从上方踩 → 第 6 帧进入 `hiding`（缩壳、未判死）、弹起 `vy = −400`；再踩 → 第 5 帧踢飞 `vel = (100, −200)`、`Solid.obstructs = false`，之后壳撞到马里奥不受伤 |
| 回归：鱼（`loadCheepSlow()` 现造一条放进 1-1） | 工厂产出的鱼带上了 `Killable`；活鱼撞马里奥仍会判死（照旧）；火球打中 → `cause = 'flip'`、掉落 85px（≈ 160px/s）；**打翻的鱼贴到马里奥身上不受伤** |

**方法坑**：这一轮的探针把「踩扁测试」的落点放在 x=440，那里**上方正好有一排砖**，马里奥根本
落不下去（`vy` 被清零、y 卡在 160）——量到的是「踩不到」而不是「踩了没反应」。换成出生点附近
的空天空区（x=100）后才拿到正确读数。

`npm run typecheck` 与 `npm run build`（1065 项校验 + tsc + vite）全过，`public/` 一字未改。


### 6.14 吃到加命蘑菇看不出「加了命」（补 1UP 飘字）

**症状**：「吃了加命的蘑菇，没有加分，也没有加一条命」。

**先分清楚哪些是原版如此、哪些是真缺反馈**：

| | 原版 / 本项目 | 实测 |
|---|---|---|
| 加命蘑菇**不加分** | **原版如此**：1-UP 只加一条命，分数不动 | `dScore = 0` ✓ |
| 加的是**真的命**（不是金币） | 本项目早已实现 | `lives 3 → 4`、`coins` 不动 ✓ |
| 音效 | 本项目早已登记 | 解码时长 **0.863s** = `1up.ogg`（现场解一份参照值对照） ✓ |
| **屏幕上看得见** | **原版关卡内 HUD 就没有命数**（`MARIO / 分数 / ×金币 / WORLD / TIME`，与原版一致）；命数只在关卡之间的 `MARIO ×N` 页和 GAME OVER 结算里出现 | 玩家在自己画面上只能看到「蘑菇没了」→ 看起来就是“什么都没发生” ✗ |

所以机制是好的，**缺的是反馈**（而且 `×NN` 是金币数，玩家很容易当命数看）。

**修法**：新增 `engine/scorePopups.ts`——用现成的位图字体（`loaders/font`）在关卡里弹一段
白色飘字：字体由 `game.ts` 加载完成后注入（与 `features/chanceBlock` 注入精灵表同一路子）；
`traits/Player.addLives` 只记一个 `pendingUps`，下一帧 `Player.update` 拿到 `level` 时才把实体
加进关卡（与 `traits/Damage` 上报死亡事件同一个路子——`collides` 里拿不到 `level`）；飘字实体
**尺寸 0×0**，所以不参与任何实体碰撞，只负责画 + 上浮 24px/s + 1 秒后自删。

**实测**（运行中的 1-1，逐帧推进 + 读画布像素）：

| 场景 | 观测 |
|---|---|
| 顶隐藏块 [64,8] → 吃绿色蘑菇 | 出来的确实是 `kind = 'one-up'`；吃掉后 `lives 3 → 4`、`dScore = 0`、飘字实体出现（`size = 0×0`） |
| 飘字画面 | 在游戏画布上抓那 24×8 区域与 `font.print('1UP')` 渲染结果逐像素比对：**76 个字形像素全部一致（mismatched = 0）**（第一次比出 116 “差异”是我把透明像素的 alpha 也算进去了，恰好 = 192 − 76，反过来证明字形是像素精确的） |
| 飘字动效 | 30 帧（0.5s）上浮 **−12px**（= 24px/s），约 1 秒后从关卡里移除 |
| 攞满 100 金币那条路 | `coins = 99` → `addCoins(1)`：`coins` 归 0、`lives +1`、飘字同样出现 |
| 变大蘑菇那条路（回归） | `+1000` 分、`small → super`（14×32）、**不飘 1UP**（`popups = 0`）——飘字只给真加命 |
| 飘字不参与碰撞 | 把它每帧贴在马里奥身上跑 5 帧：不掉血、不报错 |
| 掉命 / GAME OVER 不误弹 | `game.ts` 里 `lives -= 1` 与 GAME OVER 的 `lives = 3` 走的是直接赋值，不经过 `addLives` |

**诚实说明**：「加命时冒 1UP 小字」这条**没能查到权威出处**（SMB1 的得分飘字里确实有「1UP」字样，
但它常用于连续踩敌的奖励；马里奥 Wiki 上「collecting a 1UP Mushroom displays “1-UP” briefly」
那句话说的是 **Super Mario 64 DS**）。所以文档里按「**本项目新增**」记录，而不是写成原版行为：
它要解决的是一个真实的可玩性问题——不加飘字时玩家完全无法感知自己多了一条命。

`npm run typecheck` 与 `npm run build`（1065 项校验 + tsc + vite）全过，`public/` 一字未改。
