# Super Mario Bros. — Phaser 3 + TypeScript 复刻

对开源项目 **[meth-meth-method/super-mario](https://github.com/meth-meth-method/super-mario)**
（YouTube 系列《Code Super Mario in JS》的配套实现）的复刻。

原版是纯 vanilla JS + Canvas 2D 的无构建工程。本项目保留原版全部素材、关卡数据、
行为逻辑与渲染方式，只把 **宿主层**换成了 Vite + TypeScript + Phaser 3。

## 复刻保真度

用无头 Chrome 对两边做逐像素比对（详见 `docs/verification.md`）：

| 阶段 | 画布尺寸 | 差异像素 |
|---|---|---|
| 加载页 `Loading 1-1...` | 256×240 | **0 / 61440** |
| 关卡过渡 `WORLD 1-1 / ×3` | 256×240 | **0 / 61440** |
| 1-1 关卡画面 | 256×240 | 302 / 61440（全部集中在 Mario 所在的两格，由下方两处修复造成） |

页面布局同样一致：canvas 属性 `256x240`，CSS 盒 `1089x817`，宽高比 `1.333`（4:3）。

## 快速开始

```bash
npm install
npm run dev        # http://localhost:5173
```

> ⚠️ **必须从站点根目录访问**。原版的关卡/精灵/音乐/音效 JSON 里写的是根绝对路径
> （`/img/sprites.png`、`/levels/1-1.json`、`/audio/fx/jump.ogg`），这些数据文件保持原样，
> 因此 `vite.config.ts` 里 `base: '/'`，不能用 `file://` 直接打开 `dist/index.html`。

> 📦 仓库里同时存在 `package-lock.json`（npm）和 `pnpm-lock.yaml`（pnpm）两套锁文件。
> 当前环境只装了 npm，上面这些命令是**已验证可用**的路径。若要改用 pnpm，
> 建议先删掉 `package-lock.json` 并跑一次 `pnpm install` + `pnpm approve-builds`，
> 避免两套锁文件互相漂移。

```bash
npm run build      # validate -> tsc --noEmit -> vite build  ->  dist/
npm run preview    # http://localhost:4173
npm run validate   # 关卡与素材引用完整性校验（1065 项）
npm run typecheck
```

## 操作

进入页面后**先点击一次**（解锁音频并开始加载，与原版一致），然后：

| 按键 | 作用 |
|---|---|
| `A` / `D` | 左 / 右 |
| `W` / `S` | 上 / 下（管道方向） |
| `P` | A 键 —— 跳跃 |
| `O` | B 键 —— 加速跑 |
| `M` | 背景音乐开 / 关（也可以点页面右下角的开关） |

按键映射是原版 `KEYMAP` 的**原样保留**（原版没有映射方向键，本项目也未添加）。
原版只有键盘操作，没有触屏方案，本项目保持一致。

`M` 是新增的音乐开关快捷键，它挂在 `window` 上单独处理，没有动 `KEYMAP`
（原版映射里也没有空闲键位可用）。

## 与原版的差异

原版有三处非常规行为。前两处会让人误以为游戏坏了，因此做了修复；第三处是原版的
视觉特征，保留。

| # | 原版 | 本项目 |
|---|---|---|
| 1 | `splice(layers.length - 1, 0, spriteLayer)` 把角色层插在最后一层背景**之前**，于是装饰层（云/灌木/山丘/管道）画在角色之上——1-1 出生点 (40,192) 正压在大山丘上，**开局完全看不到 Mario** | 改为 `push`，角色层位于所有背景层之上 |
| 2 | `setupLevel()` 无条件 push 碰撞调试层，画面常驻红/蓝方框 | 默认关闭；加 `?debug=1` 可还原与原版一致的输出 |
| 3 | CSS `.aspect-4-3` 把 256×240 拉伸成 4:3（横向 ×1.25） | 原样保留 |

## 本项目新增的功能

原版是教学演示，下面这些它没有做。本项目在**不修改 `public/` 任何文件**的前提下补齐：
与关卡数据有关的走 `src/engine/features/` 下的特性模块（见「架构」一节），蘑菇和音乐开关
则分别是新实体 / 新页面模块。

| 功能 | 原版 | 本项目 |
|---|---|---|
| **顶问号块** | `chance` 的 behavior 是 `ground`，只是实心块，顶上去毫无反应 | 注册 `chance` 瓦片行为：方块上弹 10px / 0.2s，随即变成**已使用的实心块**（一次性，不再出物、不再上弹）。金币 +1、分数 +200 |
| **道具系统（蘑菇 / 火花 / 火球）** | 完全没有道具系统（`public/sprites/` 里也没有道具贴图） | 装道具的问号块按**原版规则**出物：**小马里奥出变大蘑菇、大 / 火力马里奥出火花**（同一个方块对大小马里奥给不同内容，见「问号块里出什么」）。蘑菇钻出后向右走（撞墙掉头、走出平台会掉）；火花钻出后原地不动、不断闪烁。吃到蘑菇变大 +1000 分，吃到火花变成火力形态 +1000 分——**火力形态按 B 键发射火球**（250px/s、落地弹起、撞墙消失、场上最多 2 枚、打到敌人把它**打翻**：翻过来掉出画面、立刻不再能伤到马里奥，见「火花与火球」）。哪个方块装道具由关卡坐标表决定 |
| **隐藏块（含 1-UP）** | 关卡 JSON 没有「隐藏」字段，上游把原版的隐藏块按底层瓦片存成了实心的 `metal`，于是它们**默认就画出来了**（1-1 第 64 列第 8 行那枚孤零零的方块就是原版的隐藏 1-UP 块） | 关卡数据里每个 `metal` 瓦片都当作**隐藏块**：默认不绘制、依然实心、从下方顶开才现身（换成已使用方块），再按内容表出货——1-1 那枚顶出**绿色加命蘑菇**（加一条命、不加分、响 1-UP 音效） |
| **蹲下（按 ↓）** | 完全没有这条规则，而 `public/sprites/mario.json` 里 `crouch-large` 那一帧从上游起就存在、从来没被画过 | 按原版规则补上：**只有大 / 火力形态能蹲**（小马里奥按 ↓ 没反应），要求站在地上，蹲下时**不能走、不能跳**、碰撞盒只有 16 高（能蹲着过一格高的缝），松开 ↓ 站起来（**头顶 16px 内有实心瓦片时站不起来**，继续蹲着）。见「蹲下（按 ↓）」 |
| **受伤与死亡** | 完全没有结算：怪物 Behavior 里确实会 `Killable.kill()` 到马里奥，但马里奥这一侧对 `dead` 毫无反应（`removeAfter = Infinity`，既不会消失也不会停），落坑、时间归零也没人管 | 接上三条死亡路径：被怪物碰到（**大马里奥先变小 + 1.5s 无敌闪烁**，小马里奥死亡）、掉出画面底部、关卡时间归零。死亡播原版的 `die` 姿势（上抛 → 穿地形掉落），然后扣一条命、停搮音乐、重开本关；命扣光就播 `GAME OVER` 再从 1-1 重来（成绩归零） |
| **会上下移动的平台（升降桥）** | 完全没有会动的平台，关卡 JSON 里也**没有任何平台实体**——1-2 结尾那两道 7 格宽（112px）的坑因此过不去（马里奥最远只能跳约 105px），玩家会卡在第二关里 | 新增 `traits/Lift` + `entities/Lift`：在自己行程内匀速往返、**把站在上面的马里奥一起带着走**（上行下行都贴住），并且站在上面仍能起跳。1-2 的两道坑上各放一台 3 格宽的升降桥（外观用地下关的硬块 `metal`），**左边的下行、右边的上行**——与原版攻略的描述一致（见「1-2 的两道坑与升降桥」） |
| **1-2 结尾的横管（过关）** | 管子的瓦片是有的，但 JSON 里没有 `pipe-portal` 实体，于是它只是装饰：走进去什么都不会发生，1-2 也无法过关 | 按管口瓦片注入上游的 `pipe-portal`（`features/exitPipe.ts`）→ 进入本来就存在、却一直没人用过的 `uw-exit`（原版「地下出口」：天空下的旗杆 + 城堡）。到了那边抓杆、走进城堡，再按推进表去 1-3 |
| **背景音乐开关** | 音乐只能一直开着：`playTrack()` 无条件 `play()` | 页面**右下角**一个开关（也可以按 `M`）：关掉时正在放的曲子当场静音、打开时从原处接着放；选择记进 `localStorage`，刷新/下一次打开沿用（默认开） |
| **音效与音乐补全** | 上游只登记了 5 个音效（coin / jump / stomp / break / ride）、每关的主题曲——`public/audio/` 里另外 14 个音效与 8 首曲子从未被登记也从未播放过 | 补上原版的死亡小曲、GAME OVER 小曲、过关小曲（抓旗滑到底起播）、抓杆音效、踢龟壳、大马里奥的跳跃声（见「音效与音乐」一节） |
| **旗杆上的旗子** | `flag-pole-green` 图案只有顶球 + 杆 + 底座，**整个素材库没有旗子贴图** | 运行时用 Canvas2D 现画三角旗（NES 调色板），并补上原版 1-1 缺失的旗杆实体；有人抓杆时旗子以 100px/s 沿杆下滑 |
| **走进城堡通关** | 1-1 的 `triggers` 是空数组，走进城堡什么也不会发生 | 扫描 `castle-arch` 门，在门洞注入 `goto` 触发；按 `1-1→1-2→…→7-3→1-1` 推进到下一关。**门要挑对**：一关里可能有好几座城堡（1-3 起点那座是装饰，终点那三扇才是出口），规则是「取旗杆右侧最近的一枚」（题外：原先取最靠左的那枚，于是 1-3 一出生就站在起点城堡的触发区里、**开场直接被跳过去**） |
| **砖块内容系统** | 上游所有砖（`brick`）只认「大马里奥顶碎」一种结局；小马里奥顶砖也会整块消失（上游只有小马里奥，没暴露） | **小马里奥顶砖只弹一下**（上弹动画 + `brick-bump` 音效，砖保留），**大 / 火力马里奥**才顶碎（四片碎片）；**内容砖**谁顶都不碎：多金币砖（1-1 第 94 列，10 枚金币顶完变已使用块）与**星砖**（1-1 第 101 列，出无敌星），坐标出处为早年那版 `_backup/js/level.js` 的字符地图 |
| **无敌星** | 完全没有（素材里没有贴图） | 从星砖钻出（现画 16x16 像素图 + 两帧闪光），落地弹起、撞墙掉头；吃到后**约 10.5 秒无敌**：调色板闪烁（正常帧 / 火力帧交替）、**碰到的敌人一律打翻**（含食人花——补了它缺失的 `Killable`）、循环播放 `starman.ogg`，效果结束恢复关卡主题曲（处于 hurry 则恢复加速版）；音乐开关对它同样生效 |
| **旗杆抓杆得分与计时冻结** | 抓杆只滑杆，不计分、TIME 继续倒走 | 抓杆瞬间**冻结关卡计时**（原版如此），并按抓杆高度五档计分：100 / 400 / 800 / 2000 / 5000，分数冒在旗杆上 |
| **得分飘字** | 只有踩扁 +100 进分数，画面上什么都不冒 | 原版各类得分都会冒白字：踩扁 `100`、瓦片 / 方块金币 `200`、吃道具 `1000`、旗杆得分、1-UP（原有）——统一走 `scorePopups` |
| **城堡通关收尾序列** | 走进城堡门立刻切下一关，过关小曲被拦腰掐断，剩余时间白白浪费 | 按原版节奏补齐：进门后**自动走位**（无视输入、无敌）→ 马里奥**消失在门洞里** → **剩余时间换分**（1 单位 = 50 分，快速滚分）→ 等过关小曲放完（城堡关起播 `castle-clear.ogg`——这支曲子此前永远响不了）→ 才切下一关 |
| **龟壳连击** | 滑行中的龟壳对其他敌人毫无威胁 | 原版规则：滑行壳撞到板栗仔 / 乌龟（含缩壳）/ 子弹 / 鱼 / 食人花，把它们**打翻**，并响踢壳声 |
| **1-2 的上游遗留触发器** | 关卡 JSON 里有一个写死「回 1-1」的 `goto` 触发器（(64,64)，上游没有推进表时代的出口替身），就在出生坠落路径边上，起跳就能碰到 | 按关卡在补丁表里禁用（`disableUpstreamTriggers`）：1-2 的真出口是注入的结尾横管 → uw-exit → 1-3 |

### 顶过的问号块长什么样

素材里没有专门的「已使用」贴图，于是复用 `tiles.png` 里的实心块（本项目的 `metal`）：
它是一张带四角铆钉的实心方块图，三张含 `chance` 的精灵表（overworld / underworld /
castle）都定义了它，顶完换过去不需要新增素材，也没有离开原版调色板。（这个巧合很合适：
上游把原版隐藏块也存成了 `metal`，所以隐藏块现身、问号块用过，用的是同一格贴图。）

**修复记录**：本项目的问号块最初照搬了上游「顶完还是问号块」的表现，结果是同一个方块可以
无限刷金币/分数。现在顶过一次就换成实心块（外观 + 行为都换掉），与 SMB 的一次性语义一致。

**修复记录（顶起时底下那半块「灰石块」）**：方块上弹的位移原本按**格子坐标**记录，而关卡有多层
背景（1-1 是「天空 + 地面」一层、真正的瓦片一层），两层都会读到同一个偏移——于是天空层里那一格
也跟着上移。天空是不透明的，它一移开就在原位留下 10px 的**透明洞**；`Compositor.draw()`（与上游
逐字一致）并不清画布，所以这个洞会漏出**上一帧**的像素，看上去就是被顶起的方块下面还粘着半块旧
方块。现在偏移连同**被顶的那个瓦片对象**一起记录（`layers/background.ts` 的 `tileOffsets`），
绘制时只对同一个对象生效（`bump.tile === tile`）：同格的天空留在原位，洞也就不存在了。

### 问号块里出什么

上游关卡 JSON 里没有「方块内容」字段（所有 `chance` 的 behavior 都写死成 `ground`），出什么
只能由代码自己定，于是按「关卡名 + 格子坐标」补了一张表（`features/chanceBlock.ts` 的
`POWERUP_BLOCKS`）：

| 关卡 | 装道具的方块 | 依据 |
|---|---|---|
| `1-1` | 第 **16 / 78 / 109** 列（109 列在第 5、9 行各有一枚） | 用户早年那版 `_backup/js/level.js` 里写的就是 `if (tx === 16 || tx === 78 || tx === 109)` |
| `1-2` | 开场那排五枚问号块（col 10~14）的**第一枚**（col 10） | 原版 1-2 就是「five ? Blocks. The first one contains a Magic Mushroom or Fire Flower, the other four ones contain coins」 |

其余问号块一律出金币（原版绝大多数问号块确实也是金币）。关卡 1-1 一共有 13 处
`chance` 瓦片（4 枚装道具、9 枚出金币），1-2 有 5 处（1 枚装道具、4 枚出金币）。

装道具的方块出什么**由马里奥顶它那一刻的大小决定**，这是原版 SMB 的规则：

| 顶方块时的马里奥 | 出什么 |
|---|---|
| 小马里奥 | **变大蘑菇**（红伞）：吃掉变大 +1000 分 |
| 大马里奥 / 火力马里奥 | **火花**：吃掉变成火力形态 +1000 分（已经是大号时吃到也照样加分） |

**修复记录**：本项目最初没有关卡级的内容表，用的是「本关第一枚被顶开的问号块出蘑菇」这条
简化规则（README 当时也是这么写的），于是同一个方块对大小马里奥给的东西一模一样——大马里奥
去顶第一枚方块拿到的还是蘑菇，与「大马里奥出火花」的原版规则不符。现在由
`POWERUP_BLOCKS`（哪些方块装道具）+ `PowerState.large`（吃之前大不大）两个条件一起决定出物。

**修复记录（1-2 开场那排问号块）**：补内容表时最初只登记了 1-1，于是 1-2 开场的五枚问号块
（第 9 行、第 10~14 列）全落在「没登记 → 出金币」这条路上，**第一枚没有按原版给道具**。
现在 `POWERUP_BLOCKS` 里加了 `'1-2': [{ x: 10, y: 9 }]`：小马里奥顶出蘑菇、大马里奥顶出火花，
其余四枚仍旧出金币。

### 隐藏块：默认看不见的那几个方块

原版 SMB 里有一类**看不见但实心**的方块，从下方顶开才现身。关卡 JSON 里同样没有「隐藏」
这个字段：上游把原版的隐藏块按它底层的瓦片存了下来，也就是 `style: "metal"`——正好是本项目
「已使用方块」那格外观，所以顶开之后看起来就是一块用过的实心块。

判定它为隐藏块的直接证据：1-1 全图只有一处 `metal`，就在第 **64** 列第 **8** 行、大山丘正上方
悬空一块，而与 NES 版 1-1 的隐藏 1-UP 块位置一致（用户早年那版实现的注释里就写着
`Hidden 1-UP Block (at col 64, row 8)`）。因此规则是：**关卡数据里每个 `metal` 瓦片都是隐藏块**
（1-1 ×1、1-2 ×6、1-4 ×6、2-1 ×6、3-1 ×3、coin-room-2…5 各 ×1）。

顶出来的是什么也没记录，所以按「关卡名 + 格子坐标」补了一张表（`features/chanceBlock.ts`
的 `HIDDEN_BLOCK_CONTENTS`）：

| 关卡 | 坐标 | 内容 |
|---|---|---|
| `1-1` | 第 64 列第 8 行 | **1-UP 蘑菇**（原版的隐藏加命块） |
| 其余所有隐藏块 | — | 金币（原版隐藏块最常见的内容） |

实现分担在三个地方：`TileResolver.Tile` 加了一个 `hidden?: boolean` 标记；`layers/background.ts`
绘制时跳过带这个标记的瓦片（实心与否完全不受影响）；`features/chanceBlock.ts` 在关卡加载时把
`metal` 瓦片换成带 `behavior: 'hidden'` 的新对象，并注册与问号块同构的处理器——顶开的那一瞬间
`hidden` 清掉、`behavior` 换成 `ground`，于是方块现身并永久变成普通实心块（一次性，再顶不出东西）。

⚠️ 一处需要留意：`3-1` 的 `metal` 瓦片在 JSON 里没有 `behavior`（上游没给它碰撞），本项目按
「隐藏块都是实心的」统一补上了实心。若某关的隐藏块位置看起来不对，改 `HIDDEN_BLOCK_CONTENTS`
或这处扫描规则即可。

1-UP 蘑菇与变大蘑菇是同一张 16×16 像素图、只换伞盖颜色（`#1b9d00`，即 `tiles.png` 里的水管绿，
和原版一样）。吃到它**不加分、只加一条命**，并播放 `public/audio/fx/1up.ogg`——这段音效上游的
`sounds/mario.json` 没有登记，而 `public/` 不能改，所以由 `entities/Mushroom.ts` 的
`registerOneUpSound()` 在装载马里奥时按 URL 解码后补进同一张音效板（100 枚金币换一命也会响它）。
注意 HUD 上的 `×NN` 是**金币数**，命数要到关卡开头的 `MARIO ×N` 过渡页才看得到。

### 蘑菇长什么样、怎么出来

`public/sprites/` 下 14 张精灵表里**没有任何蘑菇（也没有火花 / 无敌星）贴图**，所以 16×16 的
图形和旗子一样在运行时用 Canvas2D 现画（`entities/Mushroom.ts`：红伞 + 白斑 + 奶油色菌柄 +
黑眼睛，颜色取自 `tiles.png` 的调色板）。两种蘑菇共用这一张 16×16 像素图，只换伞盖颜色——
红色的从问号块里出来（变大），绿色的从隐藏块里出来（加命，见上一节）。
变大后的马里奥则**不需要新素材**：`mario.png` 里本来就有一整套没人用过的
大号动作帧（`idle-large` / `run-*-large` / `jump-large`），`entities/Mario.ts` 按 `PowerState.large`
切换过去。

出来与走动的手感按原版：

- **钻出**：先锁住速度、每帧向上位移，只画方块顶边以上的部分，0.5s 冒完一个身位，看起来
  才像从方块里钻出来；
- **走动**：钻出后向右走 45px/s（比敌人慢，玩家来得及追），重力与瓦片碰撞直接复用上游的
  `Physics` + `Solid` + `PendulumMove`，所以撞墙掉头、走出平台掉下去都是免费的；
- **拾取**：碰到马里奥 → 变大（14×32、脚不动）+1000 分 → 蘑菇消失（`Killable.removeAfter = 0`）；
  1-UP 蘑菇则是**加一条命、不加分**（与原版一致），响 1-UP 音效，并在头顶冒出白色「1UP」飘字。
  **为什么必须有飘字**：关卡内的 HUD 里**没有命数**（与原版一致：只画 `MARIO / 分数 / ×金币 /
  WORLD / TIME`），命数只在关卡之间的 `MARIO ×N` 页和 GAME OVER 结算里出现——不加飘字的话，
  吃加命蘑菇在自己画面上看起来就是「什么都没发生」（唯一反馈是音效，音乐一开还容易被盖过去）。
  飘字实现在 `scorePopups.ts`，掉命（`lives -= 1`）与 GAME OVER 重置（`lives = 3`）走的是
  另一条路，不会误弹。
  **钻出动画期间不可拾取**：否则马里奥贴着方块底边顶它时，两者包围盒会在蘑菇还没冒出方块
  之前就重叠，蘑菇会被瞬间吃掉 —— 玩家只看到分数 +1000、马里奥变大，却看不到蘑菇（这正是
  本次修掉的 bug）；
- **同一枚蘑菇不会被重复吃**：`Killable.dead` 之后不再触发，大马里奥再吃只加分、尺寸不变。

**修复记录**：蘑菇最初把「只画方块顶边以上部分」这条裁剪无条件套在所有帧上，于是它一走出
方块、掉到方正顶上以下时就整只被裁没了 —— 看上去就是「顶了方块却不见蘑菇」。现在裁剪只在
钻出期间生效，钻完之后整只都画。

### 火花与火球（原来完全没有）

`public/sprites/` 里同样没有火花贴图，所以 16×16 的火花和蘑菇一样在运行时用 Canvas2D 现画
（`entities/FireFlower.ts`：花瓣 + 白圈 + 红心 + 绿茎，颜色取自 `tiles.png`），并且**两套
调色板每 0.12s 轮换**，看起来就是原版火花那种不断发光的感觉。它与蘑菇共用 `traits/Emerging`
（钻出位移 + 「只画方块顶边以上部分」的裁剪）：

- **钻出后原地不动**（原版如此）：没有 `Physics`，既不受重力也不做瓦片碰撞；
- **吃掉**：`PowerState.empower()` → 火力形态 +1000 分。小马里奥吃到也直接变成大号火力形态
  （原版如此：火花永远给「变大 + 火力」）。钻出期间同样不可拾取。

火力形态**不需要新素材**：`mario.png` 里没有独立的火力帧（原版也只是同一套帧换调色板），
所以 `entities/Mario.ts` 在绘制时按帧名把大马里奥那几帧重画一套颜色——帽子 / 上衣 `#bd4131`
红 → 白、背带褲 `#797b00` 橄榄 → 红，正是原版火力马里奥（白衣红褲）的换色规则，结果按
帧名缓存、每帧只重画一次。

**火球**（`entities/Fireball.ts` + `traits/Fire.ts`）按 B 键（`KeyO`，原版 B 键同时是「跑」和
「发射」）发射，参数照原版：250px/s、出膛略向下、落地以 280px/s 弹起（约 1.5 格）、撞墙消失、
顶到天花板就往下落、**场上最多 2 枚**、打到敌人把它**打翻**（翻过来掉出画面，原版规则，见下）
而火球自己同时消失（一发一个）、飞出画面或活过 4 秒消失。输入那一侧完全不用改：上游的 `KEYMAP` 早就把 B 接到了
`entity.turbo()`，`entities/Mario.ts` 的 `setTurboState` 顺手登记一次发射请求，
`traits/Fire.update` 才拿得到 `level` 去放火球；只有 `PowerState.fire` 才真的发射（大马里奥按
B 只是加速）。

**打翻（原版规则）**：被火球打中的敌人会翻过来、直直掉出画面，并且**从命中的那一帧起就不再
能伤到马里奥**。翻转帧素材里没有（`sprites/*.json` 只有正常帧和踩扁帧），所以和火球 / 蘑菇
一样在绘制时现做：`traits/Flipped.ts` 包一层 `entity.draw`，绕 `offset.y + size.y` 把精灵垂直
镜像（板栗仔 16×16、乌龟 16×24、鱼 16×16 都刚好等于精灵高度）。这一套还顺手补上了两个缺口：
被打死的敌人不再画「踩扁」帧站在原地走 2 秒；鱼也终于能被火球打死（它原本连 `Killable`
都没有）。

**为什么火球的命中判定不在 `collides` 里**：一帧的顺序是「所有实体 update」→「所有实体两两
碰撞」→「finalize」，而 `Killable.kill()` 的 `dead = true` 要等到最后的 `finalize` 才生效。
如果命中判定留在碰撞阶段，它和「敌人撞到马里奥」就是同一轮里的两件事，先后只取决于实体在
集合里的插入顺序——而马里奥永远排在新生成的火球前面。近距离对射时就变成「火球在这一帧打死
了它、它在同一帧里也打死了马里奥」（实测：面前 4px 处对射，修复前同帧两败俱伤，修复后马里奥
不掉血）。所以命中判定搬进 `update`（Physics 之后、碰撞之前），`Killable` 也补了一个立即生效
的 `killed` 标志供杀伤判定使用。

### 1-2 的两道坑与升降桥（原来过不去）

原版 1-2 的结尾有两道 **7 格宽（112px）** 的坑，坑上各有一台**上下移动的平台**。上游移植版
没有任何会动的平台，关卡 JSON 里也没有平台实体（`public/levels/1-2.json` 只有瓦片与敌人），
而马里奥最远只能跳约 105px —— 于是这两道坑是无解的，玩家会卡在第二关里出不了头。

坐标是从关卡数据自己推出来的，不靠手感调：

| 坑 | 范围 | 左右地面 | 升降桥 |
|---|---|---|---|
| 第一道 | col 138~144（x 2208~2320） | 左到 col 137、右从 col 145 | col 139~141，**下行** |
| 第二道 | col 153~159（x 2448~2560） | 左到 col 152、右从 col 160 | col 154~156，**上行** |

「左边那台往下走、右边那台往上走」正是原版攻略的描述（*some lifts will be rising and falling;
the first one moves down while the right one moves up*），两台每台都在 y 80（天花板下方一格）
与 y 208（地面高度）之间往返。原版确切的速度没有记录在关卡数据里，这里取 48px/s。

实现上分两层：`traits/Lift` 只管行为（往返 + 带着乘客走 + 让乘客能起跳），`entities/Lift` 只管
外观（用地下关本来就有的硬块 `metal` 横拼 3 格）；位置表在 `features/lift.ts`，要加别的关卡的
升降桥，往那张表里补一行即可。

踩上去的判定是**单向**的：只有脚底接近平台顶边、而且没有正在往上跳时才算站上去（于是能从
下方穿过、也能跳起来离开，跟原版踩平台的手感一致）；站上去之后每帧把脚底贴住平台顶面
（平台下行时也贴住，不然马里奥会掉下去），并把 `Jump.ready` 顶起来，所以他还能正常起跳。

**顺带补上了 1-2 的过关路径**：原版过完升降桥就走到一根**横着的管子**里，被送到「地下出口」
（天空下的旗杆 + 城堡）。管口的瓦片在这份数据里是有的（col 166 / row 8~9，管口朝左），但
`entities` 里没有 `pipe-portal`，所以上游它只是装饰。现在 `features/exitPipe.ts` 按管口瓦片
注入上游的传送门 → `uw-exit`（`public/levels/` 里本来就存在、却一直没人用过的关），到了那
边抓旗杆、走进城堡，再按推进表去 1-3。门户的摆法有两个要诀（都是实测出来的）：管口瓦片本身
是实心的，马里奥走到嘴前就被挡住，所以门户要**往左挪一格罩住嘴前那一格**；上游门户工厂给的
高度是 30px，而大马里奥有 32px（`Pipe.collides` 要求旅行者上下边都落在门户内），所以要**把
门户加高到 48px**，不然大号马里奥永远进不去。

### 受伤与死亡是怎么算的

上游把这个口子留着没做完：`entities/Goomba.ts`、`Koopa.ts`、`CheepCheep.ts`、`Bullet.ts`
的 Behavior 里都会调 `them.getTrait(Killable).kill()`（也就是「怪物打到了马里奥」），但马里奥
这一侧对 `Killable.dead` 没有任何反应——`entities/Mario.ts` 把 `removeAfter` 写死成
`Infinity`，于是 dead 之后他既不会消失也不会停止更新，看起来就是「撞到怪物不会死、游戏照常
进行」；落坑（没有任何代码检查马里奥掉出画面）和时间归零（`LevelTimer` 只在 < 100 时发一次
hurry 事件，之后一路减成负数）同样没人管。

`traits/Damage.ts` 把三条路径都接上，判据全部取自现成信号，**没有改任何一个敌人文件**：

| 死因 | 判据 |
|---|---|
| 被怪物碰到 | 敌人那侧已经调过的 `Killable.kill()`——把它当成「挨了一下」的信号，能不能扛住由马里奥这边决定 |
| 掉坑 | `bounds.top > 240`（画布高；相机 `pos.y` 恒为 0）。**管道穿行中不算**——纵向管道会把他往下送 |
| 时间到 | `LevelTimer.currentTime <= 0`。`traits/LevelTimer.ts` 里加了 `Math.max(0, …)`，倒计时停在 **000**（原版行为，也避免 HUD 显示成 `0-2`） |

- **大马里奥挨一下**：`PowerState.shrink()` 变小（脚不动）+ `invincibleFor = 1.5s`；无敌期间
  敌人每帧还在 `kill()`，由 `Damage` 按回去。画面上用 `globalAlpha` 闪烁（不是「不画」——
  过渡页会用同一个 `draw` 画小马里奥图标，抽到空帧就会开天窗）。
- **死亡动画**：`Solid.obstructs = false` 关掉实心碰撞，竖直位移由 `Damage` 自己定速控制
  （上抛 0.45s，再以 160px/s 穿地形下坠），水平每帧清零——所以 `Damage` 必须排在 Mario 的
  trait 最后面。用的是素材里现成的 `die` 姿势（`mario.png` 的 `[96,88,16,16]`，原版因为没做
  死亡结算，从来没画过它）。
- **上报与重开**：动画走完（掉在画面下的静默死亡则是 0.5s）发一次 `EVENT_PLAYER_DIED`，
  `game.ts` 负责扣命、停音乐，然后重开本关；命扣光就先播一块 `GAME OVER` 黑屏（3s）再回
  1-1，成绩与金币清零。
- **重生**：重生一律是小马里奥（原版如此），回到本关检查点，计时器复位。`Damage.reset()`
  由 `setupLevel()` 在每次关卡就绪后调一次，它**不动大小**，所以正常换关仍然保留蘑菇。

### 蹲下（按 ↓）

上游没有这条规则，而 `public/sprites/mario.json` 里 `crouch-large`（`[0,120,16,32]`）这一帧
从上游起就存在、从来没有代码用过它（`traits/PowerState.ts` 的注释里就提到过）。现在按原版 SMB
补上了，全部逻辑集中在 `traits/Crouch.ts`：

| 原版规则 | 实现 |
|---|---|
| **只有大 / 火力形态能蹲** | `canCrouch = PowerState.large`——小马里奥按 ↓ 什么也不发生 |
| 要求**站在地上** | 用现成信号 `Jump.ready > 0`（落地那一帧由瓦片碰撞写成 1），空中按 ↓ 无效；按着不放时**落地即蹲** |
| 蹲着**不能走 / 不能跳** | 当帧把 `vel.x` 清 0；并且 `jump.cancel()`。为此这个 trait 必须排在该 Mario 的 `Go` 之后、`Jump` 之前（特性按插入顺序跑）——否则跳跃请求已经生效了一帧，看起来就是「蹲着也能小跳一下」 |
| 蹲着碰撞盒只有 **16 高** | 与小的同一尺寸，所以能蹲着从一格高的缝里过去；尺寸变化**保持脚底不动** |
| **松开 ↓ 才站起来**，头顶有实心瓦片时站不起来 | 站起前探一下头顶那 16px（只看 `level.tileCollider.resolvers`——它就是真正参与碰撞的网格）；瓦片是否挡路由 behavior 决定（全 25 关的数据里只有 `coin` 是不实心的） |

两个实现上的坑（都已经埋进注释）：

- **帧的绘制偏置**：`crouch-large` 是 16×32 的格子、人像画在**下半格**（逐行数不透明像素：
  前 10 行全透明），而蹲着的碰撞盒只有 16 高——所以绘制时要往上偏一个身位（`entities/Mario.ts`
  里的 `offsetY = CROUCH_BOX.height - LARGE_BOX.height`），脚才落在地上。实测对齐扫描：偏移
  −16 时与精灵表帧的匹配率 0.81，偏移 0 只有 0.07。
- **尺寸换算不能用常数**：`PowerState` 里长大 / 缩小都改成按「当前高度」换算（`resize()`），
  而不是 `LARGE_BOX.height - SMALL_BOX.height` 这个常数——否则**蹲着被怪物撞一下变小**时
  会多移 16px，把马里奥塞进地面。

「按着 ↓」这个事实由 `input.ts` 的 DOWN 映射写在 `Crouch.down` 上（与 `Go.dir` 由左右键写入
同一性质），上游那行「↓ 写 `PipeTraveller.direction`」保持原样，所以蹲下不影响进管道。

### 音效与音乐：把素材里躺着没登记的曲子接上

上游只为马里奥登记了 3 个音效（`sounds/mario.json` 的 coin / jump / stomp），加上
`brick-shrapnel` 的 break、`pipe-portal` 的 pipe、`cannon` 的 shoot、`flag-pole` 的 ride，
一共 7 个；而 `public/audio/` 下有 **19 个音效 + 12 首 BGM**。本项目的硬性约定是 `public/`
一字不改，所以缺的音效只能在代码里按 URL 解码后补进音效板（`engine/fxSounds.ts`），
曲子则用一个不依赖关卡播放器的独立播放器（`engine/jingle.ts`）。

**为什么小曲不能挂在关卡的 `MusicPlayer` 上**：那个播放器是「一关一份」的，换关时
`SceneRunner.runNext()` 会调 `level.pause()` → `pauseAll()` 把它的曲目全停掉；而死亡小曲
必须**跨过关**（马里奥 1 秒后就掉出画面、关卡随即重开，但小曲还有 1.7 秒没放完——原版也是
让它在「WORLD x-x / ×N」过渡页里放完的）。

| 时机 | 曲子 / 音效 | 素材 | 说明 |
|---|---|---|---|
| 马里奥死亡（三条路径都算） | `die.ogg`（2.72s） | 原来只是「把音乐停掉」 | 死亡瞬间停主题曲 + 起播小曲 |
| 命扣光的 GAME OVER 屏 | `game-over.ogg`（3.74s） | 原来是一块静音的黑屏 | 按**死亡小曲剩余时长**排期（`jingleRemaining()`），接着它收尾再放 |
| 抓旗杆 | `flagpole.ogg`（1.13s） | 静默 | `Pole.addTraveller()` 本来就会 `sounds.add('ride')`，但旗杆是本项目自己注入的、音效板是空的；`entities/FlagPole.ts` 现在给它挂上这块板 |
| 抓杆瞬间 | 主题曲**停**（`level-clear` 之前不放任何音乐） | 原版也是抓杆即停主题曲 | `features/flag.ts` 的 `FlagSlide` 在第一次看到 traveller 时 `level.music.pause()` |
| 旗子滑到底（＝马里奥落地走向城堡） | `level-clear.ogg`（5.50s） | 静默 | 城堡关选 `castle-clear.ogg`（见下方注） |
| 从侧面碰龟壳把它踢出去 / 横向踩飞壳 | `kick.ogg`（0.20s） | 静默（乌龟也没挂音效板） | `entities/Koopa.ts` |
| 跳跃 | 小马里奥 `jump.ogg` / 大马里奥 `jump-large.ogg` | 只有小的那份被登记过 | `traits/Jump.ts` 按 `PowerState.large` 选 |

> **城堡关那一支还走不到**：本工程的城堡关（1-4 / 2-4）`musicSheet` 是 `castle`，但它们的图案
> 里根本没有旗杆（只有 overworld-pattern 才有顶球），过关靠的是走进城堡门（`features/castle.ts`），
> 所以 `castle-clear.ogg` 目前只是**登记好、选择逻辑也写好了**，等城堡关有了旗杆（或给门那条路
> 也配上小曲）就会生效。

**仍然没用上的素材**（以及为什么）：

| 素材 | 为什么没接 |
|---|---|

## ⚠️ 关于原版的完成度

原版**不是一个完整的游戏**，而是一个教学演示。本项目作为复刻，在补齐上表那些功能之后，
仍然如实继承了它的这些限制：

- **道具系统已补齐**：`TileCollider` 注册了 `brick` / `coin` / `ground`（加本项目新增的
  `chance` / `hidden`）五种行为。蘑菇（红变大 / 绿加命）、火花（火力形态 + 火球）、
  **无敌星**（星砖顶出，约 10.5 秒无敌 + 打翻碰到的敌人 + 星星主题曲）都是新增的
  （素材里没有它们的贴图，全部现画）。火球只打「敌人」：判据是 `Killable.removeAfter > 0`
  的实体，道具（`removeAfter = 0`，吃到才消失）与马里奥（`Infinity`）都被排除，
  打中即判死（打翻，见「火花与火球」）、火球同时消失。`TileCollider` 仍缺
  上游没有的其余行为（如砖里藏的多金币以外内容按 `levelPatches` 的表来）。
- **死亡结算是新增的**：原版根本没做（见上表）。本项目补上了三条死亡路径、死亡小曲与
  GAME OVER 小曲（见「音效与音乐」），但没有「继续」「命数选择」这类标题菜单。
  重生一律是小马里奥、回到本关检查点（`checkpoints[0]`，也就是关卡开头），成绩与金币保留。
- **关卡推进表是新增的**：原版只有 3 个关卡带 `triggers`，不存在「世界推进」的概念。

如果想要更完整的游戏体验（道具系统、死亡结算等），需要继续在上游基础上
补齐——那属于新功能，不是复刻。

### 为什么不改关卡 JSON

本项目的硬性约定是 **`public/` 下的文件逐字节保持原版**。而「旗杆实体」「城堡通关触发」
「可顶的问号块」都依赖于关卡数据（1-1 的 JSON 里既没有 `flag-pole` 实体、`triggers` 也是
空的、`chance` 块的 behavior 写死成 `ground`），所以不能靠改 JSON 来加。

做法是在 `engine/levelFeatures.ts` 提供扩展点：每个特性模块调用
`registerLevelFeature({ name, setup(level, ctx) })`，`loaders/level.ts` 在关卡构建完成后
调用它们。特性可以扫描瓦片网格定位（`findTiles` / `findFirstTile`）、注入实体、监听事件、
追加渲染层。好处是：

- 关卡数据保持原样，特性与数据解耦（换成别的关卡也能自动定位旗杆/城堡）
- 每个特性各占一个文件，互不干扰
- 上游移植代码（`traits/`、`entities/`、`loaders/`）基本不动

移植原则：**逻辑照搬，类型补齐**。物理常量、跳帧窗口、无敌时间、敌人状态机、
管道插值、旗杆下滑速度等数值一律未改。

### 关卡内容数据集中在 levelPatches.ts

上面说的扩展点解决的是「**怎么找**」，而「**找到了之后是什么**」是纯数据：哪个问号块装道具、
隐藏块顶出来是什么、升降桥放在哪、结尾横管通向哪里、走进城堡门去哪一关。这些数据原先散在
四个 `features/*.ts` 的顶层各写一张 `Record<关卡名, 数据>`，想知道 1-2 有什么得把 features/
翻一遍，新增一关内容还要同时改好几个模块。

现在它们收拢在 **`src/engine/levelPatches.ts`** 一份按关卡聚合的表里：

```ts
patchFor('1-2') // => { powerUpBlocks, lifts, exitPipes, nextLevel }
```

三条约定：

- **只放数据，不放行为**。「怎么扫瓦片找管口」「怎么把 3 格 `metal` 拼成桥」属于实现，
  留在各自的特性模块里；
- **不放扫描得出来的东西**。旗杆位置（顶球瓦片）、城堡门（`castle-arch`）、隐藏块本身
  （关卡数据里的 `metal` 瓦片）都是从关卡数据里定位的，不在表里重复声明；
- 缺省就是「什么都不加」：`patchFor()` 对没登记的关卡返回空表，特性模块照旧跳过。

每条数据后面都留着「为什么是这个值」的出处（原版布局 / 上游 JSON / 早年那版 `level.js`），
因为这些信息在关卡 JSON 里已经不存在了，改的时候需要能核对。


## 第二轮对齐的修复记录

在功能补齐之外，本轮还修掉了一组行为与注释 / 预期不符或暴露出来的缺陷：

- **小马里奥顶砖会碎**：上游只有小马里奥，砖块处理器无条件「顶即碎」。接入道具系统后
  这条不再成立——现按原版改为小马里奥只弹、大马里奥才碎（见上表「砖块内容系统」）。
- **GAME OVER 小曲排期会掐断死亡小曲**：`playJingle()` 原实现一进来就 `stopJingle()`，
  按「死亡小曲剩余时长」排期 GAME OVER 小曲的同时把正在放的死亡小曲停掉了——
  「先听完死亡小曲」变成了「放一半被掐」。`playJingle` 增加 `interrupt` 选项，
  排期接续时不再掐当前曲。
- **排期中的小曲不受音乐开关控制**：音乐开关的订阅只静音正在播的小曲，不清还没开播的
  `setTimeout` 排期——GAME OVER 小曲排期途中关掉音乐，到点照样响。现在开关关闭会
  一并取消排期，开播前也复查开关。
- **过关小曲在城堡门被掐断**：`goto` 触发即 `stopJingle()` 的旧流程把 `level-clear`
  （5.5s）掐在进门那刻。收尾序列接管后（见上表），小曲放完才切关。
- **hurry 轨缺失会炸掉游戏循环**：`playTrack('hurry')` 对只有 `main` 的音乐表
  （uw-entrance / coin-clouds）会抛 TypeError 一路上抛打断 rAF。缺轨时降级为
  加速主题曲。`AudioContext` 也补了解锁兜底（个别浏览器手势时序下可能 suspended，
  症状是音效全哑）。
- **通关自动走位的状态泄漏**：收尾序列把 `Go.dir` 钉在 1，而 trait 跨关卡存活——
  马里奥会在下一关出生点自己向右走。`bootstrapPlayer` 现在清理跨关残留的行走 /
  蹲下状态，`EndWalk` 到达后自摘。
- **1-2 的上游遗留触发器**：见上表末行——它会把玩家莫名拽回 1-1。
- **杂项**：`fxSounds` 单个音效解码失败不再炸整个启动流程；`MusicPlayer.play()` 补了
  `.catch`（`silent.json` 的空 url 会产生 unhandled rejection）；`Stomper` 补了
  `killed` 一致性检查；`layers/collision.ts` 头注释更正为「默认关、`?debug=1` 开」；
  `Scene.pause` 不再打调试日志；`package.json` 补了 `engines: node >= 18`
  （Vite 5 在 Node 16 下会以 `crypto.getRandomValues` 报错直接崩）。
